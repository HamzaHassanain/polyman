# CLAUDE.md — Orientation for this polyman problem

You are inside a Codeforces/Polygon problem package created by [polyman](https://github.com/HamzaHassanain/polyman). Everything is described by `Config.json` at the root. Per-component rules live in [`instructions/`](./instructions/) — **don't read those files unless the current task touches the component they cover.**

## What we do

A "problem" is the tuple **(statement, validator, generator(s), checker, solutions, tests)**. Polyman drives the pipeline:

```
Config.json ─► polyman generate ─► testsets/<name>/   (inputs)
               polyman validate ─► validator OK on every input
               polyman run main ─► reference outputs
               polyman verify   ─► every solution gets the verdict its tag claims
```

A successful compile is **not** the bar. `polyman verify` (tag-conformance across all solutions) is.

## Layout

```
Config.json              Single source of truth.
solutions/               Solution sources (C++/Java/Python).
generators/              testlib *.cpp generators + gen-script.txt (the generation script).
validator/val.cpp        +validator_tests.json
checker/chk.cpp          +checker_tests.json   (or use a standard checker — no chk.cpp needed)
statements/<lang>/       LaTeX fragments per language.
manual/<testset>/        m-<NN>[-label].in (+optional .out)
testsets/<name>/         Generated by polyman; never hand-edit.
testlib.h                Run `polyman download-testlib` if missing.
instructions/            Per-component reference docs (read on demand).
```

## Components

| Component | Where it lives | What it's for | Reference |
| --- | --- | --- | --- |
| **Config.json** | repo root | The single source of truth that ties every other file together. | [`instructions/config.md`](./instructions/config.md) |
| **Solutions** | `solutions/` + `Config.json.solutions[]` | Reference and adversarial implementations. Each carries a `tag` (`MA`/`OK`/`WA`/`TL`/…) describing its expected verdict. | [`instructions/solutions.md`](./instructions/solutions.md) |

| **Validator** | `validator/val.cpp` + `validator_tests.json` | testlib C++ that decides whether an input is well-formed and within constraints. Exactly one per problem. | [`instructions/validator.md`](./instructions/validator.md) |
| **Checker** | `checker/chk.cpp` (custom) **or** standard via `Config.json` | Compares contestant output to the jury answer; emits `OK`/`WA`/`PE`. Default to a standard checker. | [`instructions/checker.md`](./instructions/checker.md) |
| **Statements** | `statements/<lang>/*.tex` | LaTeX fragments (`legend`, `input-format`, `output-format`, `notes`) per language. | [`instructions/statements.md`](./instructions/statements.md) |
| **Manual tests** | `manual/<testset>/m-*.in` + `Config.json.testsets[].manualTests[]` | Hand-authored test inputs with explicit Polygon indices (samples + edge cases). | [`instructions/manual-tests.md`](./instructions/manual-tests.md) |
| **C++ performance** | every C++ source on a hot path | Required standards (fast I/O, custom hash, container choice) for `MA`/`OK`/checker/validator/generator. | [`instructions/cpp-performance.md`](./instructions/cpp-performance.md) |
| **Working rules** | covers every interaction | Three modes, always/never, voice, workflow checklist. | [`instructions/working-rules.md`](./instructions/working-rules.md) |
| **CLI commands** | every polyman invocation | One file per top-level command (`new`, `generate`, `validate`, `run`, `test`, `verify`, `list`, `remote`, …). Read only the file for the command you're about to invoke. | [`instructions/commands/`](./instructions/commands/index.md) |

## How to use these docs

1. **Always read [`instructions/working-rules.md`](./instructions/working-rules.md) at the start of a session** that involves any non-trivial work in this directory. It covers the three modes (Default / Thinking / Do), the always/never list, the voice rules, and the workflow checklist that gates "done".
2. **Then read the per-component file only when the current task touches that component.** Editing a generator? Read [`generators.md`](./instructions/generators.md). Editing the script? Read [`generator-script.md`](./instructions/generator-script.md). If a turn doesn't touch a component, don't pull its file into context.
3. **Don't pre-load every instruction file.** They are intentionally split so context stays small. If a file isn't relevant to *this* turn, skip it.

## Quickest commands

```bash
polyman generate --all      # regenerate every test
polyman verify              # full pipeline (the bar for "done")
polyman list checkers       # standard checker options
```

Full per-command reference is in [`instructions/commands/`](./instructions/commands/index.md) — one file per command, read only the one you need.
