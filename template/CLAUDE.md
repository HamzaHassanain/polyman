# CLAUDE.md — Authoring rules for this polyman problem

You are working inside a Codeforces/Polygon problem package created by [polyman](https://github.com/HamzaHassanain/polyman). Everything is described by `Config.json` at the root. This file is the **only** rules document for any agent (Claude, Cursor, Aider, Codex). Rules below are non-negotiable: testlib, Polygon round-trip, and `polyman verify` enforce them.

```
Config.json ─► polyman generate ─► testsets/<name>/   (inputs)
               polyman validate ─► validator OK on every input
               polyman run main ─► reference outputs
               polyman verify   ─► every solution gets the verdict its tag claims
```

## Layout

```
Config.json              Single source of truth.
solutions/               Solution sources (C++/Java/Python).
generators/              testlib generators (*.cpp) + gen-script.txt
                         (Polygon-format script; or inline as generatorScript.script in Config.json).
validator/val.cpp        +validator_tests.json  (input + expected VALID/INVALID).
checker/chk.cpp          +checker_tests.json    (in/out/ans + expected OK/WA/PE/CRASHED).
statements/<lang>/       LaTeX fragments: legend.tex, input-format.tex, output-format.tex, notes.tex.
manual/<testset>/        m-<NN>[-label].in (+optional .out) — declared in manualTests[].
testsets/<name>/         Generated by polyman; never hand-edit.
testlib.h                Run `polyman download-testlib` if missing.
```

## Three modes — pick one per turn

Pick from what the user just said, not earlier turns. Pasting a statement is **not** permission to solve.

| Mode | Trigger | Output |
| --- | --- | --- |
| **Default** | Statement, idea, observation, no imperative. | One-line ack + one short clarifier. No code, no edits. |
| **Thinking** | "solve this", "what approach", "is constraint X reasonable", "analyze". | Algorithm sketch, complexity, edge cases. ≤5-line snippets. **No file edits.** Stop after analysis; wait for "now write it". |
| **Do** | "add", "write", "fix", "change", "remove", "create", "draft". | Edit the file. Reasoning internal; output = artifact + one sentence. |

Ambiguous? Ask one short question. Failed turn? Brief ack, no apology spiral.

## Solution tags

Every `solutions[]` entry has a `tag`. `polyman verify` fails the problem if behavior doesn't match the tag.

| Tag | Meaning | `verify` expects |
| --- | --- | --- |
| `MA` | Main correct (reference) | Passes every test. **Exactly one.** |
| `OK` | Alternative correct | Passes every test. |
| `WA` | Wrong answer | WA on at least one test. |
| `TL` | Time limit exceeded | TLE on at least one test. |
| `TO` | TLE-or-OK | Algorithmically correct, may TLE. |
| `ML` | Memory limit | MLE on at least one test. |
| `RE` | Runtime error | Crashes on at least one test. |
| `PE` | Presentation error | PE on at least one test. |
| `RJ` | Rejected (any) | Fails some test, any verdict. |

`MA` should be C++. Polygon refuses two solutions with the same stem (`acc.cpp` + `acc.java` collide).

## `Config.json` schema

- `timeLimit` (ms), `memoryLimit` (MB), `inputFile`/`outputFile` (`"stdin"`/`"stdout"` unless asked otherwise), `interactive`.
- `solutions[]` — `{ name, source, tag, sourceType }`. `sourceType`: `cpp.g++17|cpp.g++20|java.11|java.17|python.3|python.pypy3`.
- `generators[]` — `{ name, source }`. C++ only.
- `validator` — `{ name, source, testsFilePath? }`. C++ only.
- `checker` — `{ name: "ncmp", isStandard: true }` *or* `{ name, source, isStandard: false, testsFilePath? }`.
- `testsets[]`:
  - `generatorScript: { script? | scriptFile? }` — Polygon-format text (see below).
  - `manualTests[]` — `{ input, output?, index, group?, points?, useInStatements? }`.
  - `groupsEnabled?`, `groups[]?`.

## Generator-script syntax (Polygon-format)

Each non-comment line: `gen-name [args...] > target`.

| Target | Meaning |
| --- | --- |
| `N` | Explicit test index. |
| `$` | Smallest unused index. |
| `{1-3,7}` | Multi-output: generator writes those files itself, no stdout redirect. |

- `<#-- comment -->` stripped. `<#-- @group <name> -->` headers tag every following line.
- `<#list a..b as i> ... ${i} ... </#list>` expanded.
- Generator names must **not** include extensions (`gen.exe`, `gen.cpp` are rejected).
- Indices must be unique across the script and `manualTests[]`.

Example:
```
<#-- @group main -->
<#list 1..50 as i>
gen-random ${i} > $
</#list>
```

## Statements — `statements/<lang>/*.tex`

Four LaTeX fragments per language, **not** standalone documents (no `\documentclass`).

- `legend.tex` — story; what to compute. **No constraints, no spoilers, no "use DP".**
- `input-format.tex` — input layout + constraints (`$1 \le n \le 10^5$`, in a bullet list).
- `output-format.tex` — output layout.
- `notes.tex` — sample walkthroughs, edge-case explanations.
- **Never put sample I/O in `.tex`.** Samples are `manualTests[]` with `useInStatements: true`; Polygon renders them.
- Math: `$...$` inline, `$$...$$` display. Use `\le \ge \cdot \ldots \times \bmod`.
- `english/` is required.
- **Do not create or translate the Russian statement unless the user explicitly asks.** The template ships `statements/russian/` as a placeholder; if the user isn't translating, leave it alone or delete it — never auto-fill it from the English version, and never remove it from `Config.json.statements` without confirmation.

## Generators — `generators/*.cpp`

```cpp
#include "testlib.h"
using namespace std;
int main(int argc, char* argv[]) {
    registerGen(argc, argv, 1);
    int n = rnd.next(1, atoi(argv[1]) * 100);   // size scales with seed
    cout << n << "\n";
    for (int i = 0; i < n; ++i)
        cout << rnd.next(1, 1'000'000'000) << (i+1==n ? "\n" : " ");
}
```

- `registerGen(argc, argv, 1)` first.
- Read CLI args **positionally** (`argv[1]`, `argv[2]`, …). **No** `opt<T>("name")`.
- Output to stdout. Deterministic given the same args (no `srand`, no `time(NULL)`).
- Output must satisfy the validator. After authoring: `polyman generate --all && polyman validate --all`.

## Validator — `validator/val.cpp`

```cpp
#include "testlib.h"
using namespace std;
int main(int argc, char* argv[]) {
    registerValidation(argc, argv);
    int n = inf.readInt(1, 100'000, "n");
    inf.readEoln();
    for (int i = 0; i < n; ++i) {
        inf.readInt(1, 1'000'000'000, "a_i");
        if (i+1 < n) inf.readSpace();
    }
    inf.readEoln(); inf.readEof();
}
```

- `registerValidation` first. Read every value via `inf.readInt(LO, HI, "name")` / `inf.readToken(...)`. **Never** raw `cin`.
- End with `inf.readEoln(); inf.readEof();`.
- Constraints in the validator **must match** `input-format.tex`. Tighten one → tighten the other → update `validator_tests.json`.
- `polyman test validator` after edits.

## Checker — `checker/chk.cpp` or standard

**Default to a standard checker.** Only write a custom checker when the output has multiple valid forms (any minimum-cost path, any valid permutation, …).

### Use a standard checker

Pick by output shape (`polyman list checkers` shows the full set):

| Checker | Use when output is |
| --- | --- |
| `ncmp` | Sequence of integers (most problems). |
| `wcmp` | Sequence of whitespace-separated tokens (strings + numbers). |
| `lcmp` | Compared line-by-line; whitespace inside a line is normalized. |
| `yesno` | A single `Yes`/`No` (case-insensitive). |
| `dcmp` | Floating-point with absolute/relative error 1e-6. |
| `rcmp4` / `rcmp6` / `rcmp9` | Floating-point with N decimal places. |
| `fcmp` | Exact file comparison, no normalization. |

Wire it up in `Config.json` — that is the entire change:

```json
"checker": { "name": "ncmp", "source": "ncmp.cpp", "isStandard": true }
```

`name` and `source` use the same string (the checker's filename without the path; polyman pulls it from its bundled `assets/checkers/`). With `isStandard: true`, polyman ignores any local `checker/chk.cpp` — keep the file or delete it. No `testsFilePath`; standard checkers are not self-tested. Run `polyman verify` to confirm everything still passes.

### Switching from custom → standard (or back)

1. `polyman list checkers` → pick the right standard.
2. Replace the entire `"checker": { … }` block with the standard form above.
3. `polyman verify`. If solutions still pass, you're done — `checker/chk.cpp` and `checker/checker_tests.json` become unused (delete them or leave them).

### Custom checker rules

If a standard checker doesn't fit, write `checker/chk.cpp`:

```cpp
#include "testlib.h"
using namespace std;
int main(int argc, char* argv[]) {
    setName("compare integers");
    registerTestlibCmd(argc, argv);
    long long ja = ans.readLong();
    long long pa = ouf.readLong();
    if (ja == pa) quitf(_ok, "%lld", ja);
    quitf(_wa, "expected %lld, found %lld", ja, pa);
}
```

```json
"checker": { "name": "chk", "source": "./checker/chk.cpp",
             "isStandard": false, "testsFilePath": "./checker/checker_tests.json" }
```

1. `#include "testlib.h"` and `registerTestlibCmd(argc, argv)` first.
2. Read input from `inf`, contestant output from `ouf`, jury answer from `ans`.
3. End with **one** of `quitf(_ok, ...)`, `quitf(_wa, ...)`, `quitf(_pe, ...)`. `_fail` only for jury bugs (malformed answer file), never for contestant errors.
4. Self-tests in `checker/checker_tests.json` covering OK/WA/PE/CRASHED. Run `polyman test checker`.
5. Floating-point: never `==`. Use a tolerance.

## Manual tests — `manual/<testset>/m-<NN>[-label].in`

```jsonc
"manualTests": [
  { "input": "./manual/tests/m-01-sample.in",
    "output": "./manual/tests/m-01-sample.out",   // optional reference answer
    "index": 1, "group": "samples", "useInStatements": true }
]
```

- Samples → `group: "samples"`, `useInStatements: true`. 2-3 samples typical.
- Hand-crafted edge cases → their own group (e.g. `"edge"`), `useInStatements: false`.
- `index` is unique across script + manuals. Renumbering means renaming the file too.
- Files must satisfy the validator.

## C++ performance — required for `MA`/`OK`/checker/validator/generator on hot paths

```cpp
ios_base::sync_with_stdio(false);
cin.tie(nullptr);
```

- Use `"\n"`, never `endl` (flushing dominates).
- `vector` over `set`/`map`/`list` unless you need ordered traversal or true `O(log n)`.
- `unordered_map<int, …>` needs a custom hash to defeat anti-hash tests (splitmix64).
- Pass heavy objects by `const&`.

## Always / Never

**Always**:
- Read a file before editing it. Batched edits: read all, then write all.
- After changing logic in a generator/validator/checker/solution, **update the matching tests in the same edit**: cases in `validator_tests.json` / `checker_tests.json`. Bug fixes get a regression case. Deleted behavior gets its tests deleted.
- Run `polyman verify` before declaring work done. Compile success is not the bar; tag conformance is.

**Never**:
- Hand-edit `testsets/<name>/`. Regenerated by `polyman generate`.
- Skip the script (write tests directly to disk). Polygon needs the script to round-trip.
- Modify `testlib.h`. Use `polyman download-testlib`.
- Change `inputFile`/`outputFile` away from `"stdin"`/`"stdout"` without an explicit ask.
- Commit binaries.
- Spawn `g++` by hand instead of using `polyman` — limits won't be enforced.
- Run a `Edit`/`Write` blindly without prior `Read`.

## Voice

- Brief. One clear sentence > one clear paragraph. End-of-turn: 1-2 sentences on what changed.
- Push back when something's off ("n=10⁶ with O(n²) won't fit at TL=1s"). Don't agree to agree.
- No filler ("I'll do X now" — just do X. "Let me know if…" — drop it).
- Avoid AI tells: *absolutely, certainly, definitely, wonderful, fantastic, excellent, comprehensive, crucial, essential, leverage, utilize, robust, genuinely, truly, literally*.

## Workflow checklist (before declaring done)

1. `polyman validate --all` if generators / manual tests / validator changed.
2. `polyman test validator` if validator changed. `polyman test checker` if checker changed.
3. `polyman verify` if anything affecting solution outcomes changed (any solution, any test, the checker).

## Common workflows

- **New solution**: drop in `solutions/`, add `Config.json.solutions[]` entry with correct tag and `sourceType`, `polyman run X --all`, `polyman verify`.
- **New generator**: write C++ in `generators/`, add to `generators[]`, reference from `generators/gen-script.txt`, `polyman generate --all && polyman validate --all`.
- **Manual sample**: drop input at `manual/tests/m-<NN>-<label>.in` (+ optional `.out`), add to `manualTests[]`, `polyman generate --all`.
- **Tighten constraints**: validator → `input-format.tex` → `validator_tests.json` → `polyman test validator` → `polyman generate --all && polyman verify`.
- **Use a standard checker**: replace checker block with `{ "name": "ncmp", "isStandard": true }`, `polyman verify`.
- **Sync to Polygon**: `polyman remote register <key> <secret>` once, then `polyman remote push . && polyman remote commit . "msg"`. Pull: `polyman remote pull <id> .`.

## Interactive problems

Local pipeline does **not** simulate interaction. Set `interactive: true`, write a testlib interactor at `interactor/interactor.cpp` for Polygon, but rely on `polyman remote push` + Polygon-side verification. Default to non-interactive.

## CRLF on Windows

Validator/checker self-tests in `*_tests.json` may need `\r\n` instead of `\n` inside the embedded `input` strings on Windows. Match the user's OS.
